# Logs

Every file below is absent until its writer publishes it in **this** repo. Pre-run 1's files of the same names are history in [that repo](https://github.com/STP-KAS/tn10-storm-2026-11-11-prerun/tree/main/logs). They are not gates here.

| File | Who writes it | When |
|---|---|---|
| PRE-RUN-OPEN.md | the desk | after the operator's paste, once both TN10 nodes are synced, Mini has notified Build, and no other runner is up. `hashes/SIXTEEN.md` comes first and may already be on origin. One line: `PRE_RUN_OPEN` and a UTC timestamp |
| MINI-ARMED.md | Mini | after the operator pastes GO-MINI and `PRE-RUN-OPEN` is on origin. One line: `MINI_ARMED` and a UTC timestamp |
| FIXES.md | the desk | each repair. UTC time, what failed, what changed, why |
| METHOD.md | the desk | when RETURN is on origin, met or `NOT MET` |
| BOT-HALT.md | the operator | one line, any time, to stop the bot |
| FAILED.md | the desk or the operator | if the run dies before RETURN. The run is not resumed. A next attempt is a new repo |

`PRE-RUN-OPEN` is not a send. A chat sentence does not write it. There is no clock that writes it.

METHOD.md leads with accepted hops per cohort, and payment submit-OK and included per target. It says whether the result was decent or short of decent, as [README.md](../README.md) defines those words. If the rates were one rate, or the coins were not one size, or the cohorts did not share one node set, it says so and does not call the fee the whole cause. Then the misses, the fixes, and the On origin time of each count file. A fee estimate is not a row.

A worked fix is also appended to [locks/LOCKED.md](../locks/LOCKED.md). This file does not rewrite a paste.
